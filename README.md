# Sprint_10 — автотесты «Яндекс.Маршрутов»

Учебный проект на Python, pytest, Selenium и Allure. Проверяется реальный сервис
https://qa-routes.education-services.ru/. Ответы API, DOM, цены и таймеры не подменяются.

Проверено 6 ноября 2026 года на Chrome 156: **26 passed, 2 xfailed**, неожиданных падений нет.
Полный прогон занял 117,76 секунды. Журнал: [docs/last-run.txt](docs/last-run.txt).

## Подготовка

Нужны Python 3.12+, установленный Google Chrome и Node.js 24 LTS для генерации отчёта.
ChromeDriver автоматически подбирает Selenium Manager. Устаревший ChromeDriver в PATH
игнорируется настройкой `SE_SKIP_DRIVER_IN_PATH` в фикстуре. При первом запуске требуется интернет.

Откройте именно каталог `Sprint_10`, затем выполните:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm ci
```

## Запуск

```sh
python -m pytest
```

По умолчанию Chrome работает в headless-режиме с окном 1440 × 1100. Чтобы видеть браузер:

```sh
python -m pytest --headed
```

При необходимости адрес окружения можно переопределить:

```sh
python -m pytest --base-url=https://qa-routes.education-services.ru/
```

Каждый тест получает новый браузер с чистым профилем. Предусловия задают фикстуры
`route_ready`, `taxi_page`, `laptop_taxi`, `searching_order`, `assigned_order`.
Используются только явные ожидания. Поиск автомобиля завершается естественным образом;
максимальное ожидание — 90 секунд. Тесты не зависят от порядка запуска.

## Покрытие

- `test/test_route_rendering.py`, `TestRouteRendering`: две точки на карте для обоих направлений.
- `test/test_route_selection.py`, `TestRouteSelection`: блок маршрута для разных и одинаковых адресов; бесплатная поездка длительностью 0 минут.
- `test/test_taxi_preparation.py`, `TestTaxiPreparation`: оба направления переключения Оптимальный/Быстрый, пересчёт цены и времени, доступность и выбор каждого из шести типов в режиме Свой, кнопки такси и Драйва.
- `test/test_taxi_tariffs.py`, `TestTaxiTariffs`: шесть тарифов, один активный, шесть подсказок при наведении, четыре поля формы.
- `test/test_taxi_order_flow.py`, `TestTaxiOrderFlow`: Рабочий + столик, окно поиска и уменьшение таймера, полный сценарий до отмены, отдельная проверка отмены найденной машины.

Функциональность добавления прав и заказа Драйва не входит в перечисленные сценарии задания:
для Драйва проверяется требуемая доступность кнопки «Забронировать».

## Page Object и структура

`pages/` — отдельный пакет с объектами экрана маршрутов, формы такси и модального окна заказа.
`locators/` — все Selenium-локаторы, включая динамические; в тестах и Page Object их нет.
`data.py` — адреса и ожидаемые данные из ТЗ. Тесты не обращаются к WebDriver напрямую.
`conftest.py` — создание и закрытие Chrome, фикстуры, скриншот и HTML при сбое.

На одной SPA каждый видимый функциональный экран имеет собственный объект.
`RoutePage` только открывает форму, взаимодействие с её элементами выполняет `TaxiPage`.
Аналогично все действия с окном заказа находятся в `OrderModal`.

## Известные баги

Две проверки подсказок отмечены `@pytest.mark.xfail` с причиной и ограничением
`raises=AssertionError`: у тарифов «Сонный» и «Разговорчивый» перепутаны описания.
Проверки сравнивают интерфейс с ТЗ, а не с ошибочным поведением сервиса.
Подробности: [docs/bugs.md](docs/bugs.md).

`xfail_strict = true`: после исправления бага неожиданный проход станет ошибкой XPASS,
чтобы метку не забыли убрать. Ошибка локатора или таймаут не скрываются как ожидаемый баг.
Для обычных падений известных дефектов запустите:

```sh
python -m pytest test/test_taxi_tariffs.py -k tooltip --runxfail
```

## Allure

```sh
npm run report
```

Готовый автономный отчёт: `allure-report/index.html`. Его можно открыть двойным кликом
или передать вместе с папкой `allure-report`. Отчёт содержит фактические результаты,
шаги, параметры, причины XFAIL и вложения с экранами/DOM при сбоях.

Для открытия через встроенный сервер Allure:

```sh
npm run report:open
```

В репозиторий включаются исходники и готовая папка `allure-report/`.
Промежуточные `allure-results/`, окружение `.venv/` и `node_modules/` исключены через `.gitignore`.
Перед новым прогоном pytest очищает только `allure-results/`.
Генератор также очищает старый `allure-report/`, поэтому в отчёте нет смешения прогонов.

Allure 3 устанавливается локально через npm и не требует Java.
[Документация генерации](https://allurereport.org/docs/v3/generate-report/) и
[конфигурации автономного HTML](https://allurereport.org/docs/v3/configure/).

## setTimeout, hover и xfail

Для ручного исследования подсказки в DevTools можно выполнить:

```js
setTimeout(() => { debugger; }, 3000);
```

После запуска наведите мышь на `i`: отладчик остановит страницу через 3 секунды,
и можно изучить открывшуюся подсказку в Elements. Это только приём исследования,
в автотестах фиксированные задержки не используются.

В Selenium наведение выполняется через `ActionChains(driver).move_to_element(element).perform()`;
метод `BasePage.hover()` инкапсулирует его, затем тест ждёт видимую подсказку явным ожиданием.
`pytest.mark.xfail` документирует известный дефект, выполняя настоящее утверждение по ТЗ.
